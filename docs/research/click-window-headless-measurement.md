# 点击窗那一块在 headless 里到底量得到什么

2026-10-08 量。起因是工单 `.scratch/deepening/issues/02-click-window-rect.md`
写着「这一族的 `--check` 量不到，headless 的 `DisplayServer` 报的屏是 1×1」——
**那一句是读来的，不是量出来的**。本文件把那一句当没量过，重新量一遍。

判据在 `src/Fader.cs` 的 `ContentSelfTest` 末尾那一段（`clicks-probe` 那一段）。
结果从 `problems` 出去，不借日志 —— 自检里那扇窗的日志笔是空的，
而 `CODING_STANDARDS.md` 取证方法论第 5 条后半段记的就是这个
（「实测结果压根没出来，屏幕上只剩那句结论」）。

## 重量的（2026-10-08 第二发）—— 上面第一行和第五行**不复现**

工单 03 收尾那一跑的复核把这一份当没量过，重量了一遍
（同一台机器、同一条命令，`Fader.ClicksProbeReading` 那一段）。

| 那一问 | 第一发记的 | **第二发量到的** |
| --- | --- | --- |
| `GetScreenCount()` | 0 | **0**（复现） |
| `ScreenGetSize(0)` | `(0,0)` | **`(0,0)`**（复现） |
| 罩得住那颗钮 | True | **True**（复现） |
| 要罩的那一块 | `(-6,-6) (140,51)` | **`(-6,-6) (140,78)`** —— 不复现 |
| 第一行的全局矩形 | `(0,0) (0,0)` 零面积 | **`(0,0) (29,66)`，不是零面积** —— 不复现 |
| 「全部行落在里面」 | True，判成假阳性 | **True，而「第一行是零面积」= False** |

**三行复现、两行不复现。** 不复现的两行都跟**清单那几行的排版**有关：
`要罩` 那块变高了 27、而第一行从零面积变成了 `(29,66)` ——
**说明第一发量到的是「清单行还没摆出形状」，第二发量到的是「摆出来了」。**
（第一发那段记录的是 `Rect2`，第二发报的是 `Rect2I`，形状本身也换过。）

**按规矩把这一条记在这儿而不是抹掉**：第一发那两行是当时真的量到的，
而它量到的东西**不再复现** —— 说明那一发量的不是这一件事。
`CODING_STANDARDS.md` 取证方法论第 18 条「补写的文档不许假装自己验过」。

### 「`RowsInside` 是假阳性」这一条，结论要改

**第一发的理由是「零面积行矩形被任何矩形罩住，所以恒真」。第二发量到第一行不是零面积，
所以那个理由在第二发不成立。**

但**那一问仍然不能当成真判据**，理由换了：**`Encloses` 对零面积矩形恒真，
而 `RowsInside` 遍历的是全部行，代码里排掉的只有第一行**
（`Fader.ContentSelfTest` 里 `rowsDegenerate` 只看 `firstRow`）。
**第一行不是零面积，不等于每一行都不是。** 后面那些行要是零面积，
这一问对它们照样是白问 —— 而它答的是 `All`，看不出是哪一行白问了。

**所以这一问现在的准确说法是**：
「第一行不是零面积，它那一问不是白问；**其余各行有没有零面积，这一发没量**」。

**要把它变成一条真判据，得排掉每一行的零面积，不只是第一行。**
**本文件只记下这一条，不改代码** —— 那是工单 02 的活，不在本文件。

**两处和原来记着的不一样**：

1. **不是 1×1，是屏数 0。** headless 下 `DisplayServer` 根本没有屏可问，
   `GetScreenCount()` 答 0，`ScreenGetSize(0)` 答 `(0,0)`。
   1×1 那个说法是读来的。**结论的方向没变而理由更硬**：占比那一头连分母都没有，
   不是「分母是 1 所以永远 100%」，是压根算不出来。

2. **`RowsInside` 在 headless 里恒真，是个假阳性。** 零面积矩形 `(0,0) (0,0)`
   被任何矩形 `Encloses` —— 所以「清单每一行都落在点击窗那一块里」这一问在
   headless 下**答 True，而它什么也没证**。

   这一条要紧：它是 `CODING_STANDARDS.md` 取证方法论第 6 条那一条病
   （「判据里不许存一份会腐烂的副本」／判据量的是当初那份形状）。
   谁要是直接把它当判据用，它会永远绿。

   **修法已经写进代码**：`Fader.ContentSelfTest` 里问它之前先排掉零面积
   （`firstRow.Size.X <= 0 || firstRow.Size.Y <= 0` → 这一问不算数）。

## 量到了什么、量不到什么

> 下面这张表量的是**点击窗**（有窗那一版，2026-10-08）。2026-10-10 那一族改成钩子按坐标判之后，
> 「哪一头量得到、哪一头量不到」的分界没变，只是那一份多了一步裁 —— 见最后一节。

| 那一头 | headless 里 |
| --- | --- |
| 要罩的那一块非空 | **量得到** |
| 要罩的那一块罩得住那颗钮 | **量得到** |
| 换步之后该举 / 不该举 | **量得到**（原有判据已经在问） |
| 点击窗罩住整块屏百分之几 | 量不到（屏数 0，无分母） |
| 罩没罩住清单**第一行** | **量得到**（第二发量到它不是零面积，不是白问） |
| 罩没罩住清单**其余各行** | 量不到（`Encloses` 对零面积恒真，而代码只排掉了第一行） |
| 底下那些点是不是真到了别的程序 | 量不到（要 OS 那一层，`--push` / `--clicks` 那一族） |

**所以工单 02 那句「这一族的 `--check` 量不到」要改口**：
不是整族量不到，是**两头条不到**（占比、除第一行以外的逐行），
而「要罩的那一块本身」在 `--check` 里量得到 —— 而且已经量到了。

这一族原先记着的三样结论（`a43b882` 那一轮）里，
「屏是 1×1」这一条被本文件替换成「屏数 0」（**第二发复现**）；
「行矩形是 0」那一条**第一发量到、第二发没复现** —— 见上面「重量的那一发」。

## 裁过屏的那一份在 headless 下退化成 1×1（2026-10-10）

拆掉点击窗之后，「点得到的那几块」不再有窗，成为**一块矩形**交给钩子按坐标判。
矩形的算法没动（并矩形 + `Pad` 那一圈，还是同一段算术，正本搬到 `src/ClickRegion.cs`），
**新多了一步裁**：`Fader.MeasureSwallowRect` 把它和遮罩自己那一扇窗的矩形求交 ——
有窗那一版为什么要裁，是「出了屏的那一半引擎摆不上去」；钩子这一版裁的理由不一样，
是屏在休息中间变小的时候别把块算到旁边的屏上。

**量到的是**：无头下遮罩那一扇窗自己就是 `1×1`，所以求交之后那一块**退化成 `(0,0) (1,1)`**，
而**没裁的那一份**是 `(-6,-6) (140,78)`（两个数都记在这一节的判据读数里，`--check` 的
`mask-text` 那一组现问就能看到）。

**第一版判据栽在这里**：坐标那一问拿**那颗钮的中心**去问裁完的那一块 ——
`(64,19)`，而那一块是 `(0,0) (1,1)`，答「不吃」，判据当场报红。
**量到的是量具的毛病，不是产品的毛病**：两者压根不在同一片坐标上。

**现在那一问从裁完的那一块自己身上取点**（正中间），块外那一点仍取「正中间往下 4000 像素」。
两问在 headless 下都成立：`(0,0)` 在 `(0,0) (1,1)` 里、`(0,4000)` 不在。
三发反向验都响过（拆掉 `Disarm` → 3 条、`Swallows` 恒答「吃」→ 2 条、
铺满那扇不穿透 → 3 条，三次退出码都是 1）。

**「罩不罩得住那颗钮」那一问仍然问没裁的那一份**（`SwallowMerge().Encloses(EndRectFor())`）
—— 两问各管各的，混起来就又是拿一个坐标系去问另一个。
