# 实物帧量回来的那几发：遮罩与日历在屏幕上读到的数

这一族是**抓一帧再读像素**、或在**活文档上改一次再读回来**的量。都是 2026-09-25 到 09-27 那几轮界面上量到的。取向在 `docs/adr/`（遮罩那扇窗在 0003，界面与控件那条在 0001），跑测量程序的规矩在 `CODING_STANDARDS.md`，这一份只收实测结果。

- **分两层各乘一次 alpha 会合成出 `1-(1-a)²`**：纯色底和图是两层，`maxOpacityPercent` 75% 时图实际压在 93.75% 底下，19% 的绿从它身上透过去。在黑条上读 (24,72,84)，正合两层模型，而一层预测 (24,48,72)。处置：一个像素只走一次画 —— `Fill` 让位，图那一层只在图盖不到的那几条边上补纯色。判据一随之从 **843‰**（那数是图，不是字）降到五种摆法 **1.6‰–3.6‰**，残留正好落在清单那一块。
- **混色路线那一发**：`alpha=0.750` 压着白页，屏幕上读到 (68,164,116)，而「before × 25% + `#008040` × 75%」预测 (64,160,112)。
- **第一帧一次发现六件事**（`--fader-shot` 举一次预览、落定之后把同一块矩形抓下来，落盘 `docs/research/images/fader-{stage0,checklist}-live.png`；这些帧 2026-11-08 已移出仓库）：
  ① 一步只会**加**自己要显示的东西，所以钟和休息足迹还压在清单上面；
  ② 清单的字和勾是引擎默认深色，绿底上读不出来；
  ③「提前结束休息」那颗是灰的默认钮，不是 outline 那颗；
  ④ 勾上那一行不后退；
  ⑤ 根本没有「还剩 m:ss」那一行；
  ⑥ 健康度那一行印 `29%`，而形状要的是「健康度 78%」—— 那条串一直躺在语言表里没人用。
  六条到 2026-09-27 全修掉。划掉那一行现在是 `RichTextLabel`，那道线由 `CheckRow._Draw` 自己画：引擎默认字体对 bbcode `[s]` 没有 strikethrough 度量。**认下来的代价**：整行任意位置（格子、字、字与格子之间那段空白）都是命中区。
- **改一份活文档不用重启就挪窗**：`--relayout` 读到 70%/70% 的 `1792x966` 在 45%/80% 下变成 `1152x1104`，仍然挂进壁纸、仍然锚在同一块角上。
- **双击那一发是端到端量过的**：一发真点击选中格子，134 毫秒之后那一发抬窗并拿到前台，Enter 把它落回原来那个像素。它提交的那条备注是这一支第一次往 `calendar.json` 里写东西。（抬窗那一路拿到 OS 前台、没人点的那一路拿不到 —— 那一发在 `docs/research/win32-constants-and-structs.md`。）
- **输入法这一侧量不了**：抬起那扇窗现在印 `IME 上下文=… 开着=… 档=…`，这台机器读 `开着=False`，和上游那条还开着的 bug（godot#123334）对得上。拼字那一步要真键盘在人手上，所以**这是实测结果的范围，不是待办** —— 口径在契约 `.scratch/keeper-contract/spec.md`「Out of Scope」那两条。
- **注入的键在这台机器上不可靠，不再当证据**：`--sweep --edit` 那一发把字放进格子里的是测量程序，不是手，所以那跑证的是**提交路径**和**输入框落点**，不是输入法。同一发抓到一条真 defect：输入框没跟着选中的格子走，一直待在左上角那一格（这一发没记它修没修）。
- **声音那两发**：`播放器在转=True`，淡出那一段同法问 —— 两问都是问播放器自己。形状跟着那两发定下：一份播放器配一次淡入，不是一块屏一个（八块屏放八遍不是更响，是失真）；淡入那一段的 900 毫秒是老版硬写的那个数，**不是** `fadeInMs`（那个说的是画面）；`repeat` 靠 `finished` 重开，不用按格式的原生循环。`tile` 那一档同理：五种摆法从屏幕正中往外排，不从左上角起。

## 界面上活着、这一支没有读者（那一族四条）

`sound.*`、`image.*`、`blockWhenFullscreen`、关于窗口那一行，都在设置窗和托盘菜单里活着，而这一支没有任何东西读它们 —— **不是缺键，是缺读者**。同一条形状还有 `calendar.style`：2026-09-26 之前文档写着 `wallpaper` 而屏幕上是 widget；以及 `Scheduler` 的调用点在 2026-09-25 之前一直传 `blocked: false`，所以那个键做了个动作但没有效果。

## 折色与比色的取整口径（三条，正文在 `src/Frames.cs` 与 `src/App.cs`）

这一族不是实测结果、是一处**搬家**造出来的实测结果：测量程序的取色、混色、判残留原先散在几处实施里，
收成一份的时候每一处都带着自己那条算术。收得对不对靠**扫**，不靠看着像（量于 2026-09-29）。

- **`(byte/255f)*255f` 在 float 下不显然等于那个 `byte`**：`Fader.Rgb` 还回来的是 `byte/255f`，
  而测量程序原来那一份又把它乘回 255。合并成直接用字节的写法时，这两条**看着像**就相等。
  证法：扫遍 256×256×101 逐点比 `(int)Math.Round(below*(1-a) + (byte/255f)*255f*a)` 与
  `(int)Math.Round(below*(1-a) + byte*a)` —— 扫下来相同，所以合并成立，**而看着像不算证**。
  复算时注意 C# 的 `Math.Round` 是 **banker's rounding（half-to-even）**，JS 的 `Math.round` 是 half-up，
  拿后者复算会得到不一样的答案。
- **从 `Color` 取回那三个字节要四舍五入，不能 `(byte)` 截断**：`Color.R` 是 `byte/255f`，乘回 255
  在 float 下差不到 1e-4，截断会在某些字节上少 1 —— 于是搬一次家搬出一条新实测结果来，
  而且**它长得像一处像素差，不像一处取整差**。
- **`App.FrameResidual` 的期望色走 `(int)(x + 0.5f)` 截断，不是 `Math.Round`**，所以它**不能**换成
  `Frames.Blend`（后者是 banker's rounding），半格上差 1。当时只搬了比色、没搬那条算术。
  **同一件事两份取整口径，是这一族里最容易被顺手「统一」掉的一条。**

## 「读不到」是一档返回值，不是一个颜色

`GetPixel` 还回来那个数是 `CLR_INVALID`。原先的取色把它折成 `(0,0,0)`，也就是把「没读到」
伪装成「读到黑」；同一件事当时还有另一份实施，折成的是 `(-1,-1,-1)` 并自己记一行账 ——
**两份实施、处理相反**，于是两发都没读到时差是 0，`AlphaMeasurement` 印成「那一点是透的」。

现在「读不到」是取样上的一档，差值那一发在有一边没读到时给 `int.MaxValue`，于是**所有「差 ≤ N」的
判据都失败关闭**，一条都不用改。正文在 `src/Frames.cs`（`Sample` / `Gap` / `GapText`）。
