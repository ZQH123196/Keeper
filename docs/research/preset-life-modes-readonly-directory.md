# 预设生活模式那一个只读目录：读法、为什么它结构上写不进去

2026-10-02。机器：Windows，Godot 4.7.2-stable mono。工单 05（`.scratch/archive/keeper-routine/issues/05-preset-life-modes.md`）。

这份只装**量到的实测结果**和**从实测结果定下来的那条取向**。取向本身在 ADR-0005「预设生活模式不是第二种实体」，
契约在 `.scratch/keeper-contract/spec.md`；那一族的形状在 `docs/design/preset-life-mode.md`。

## 目录住在哪里

`res://presets/`（`PresetLifeModes.Dir`）。装在 `res://` 里的理由不是方便，是**打包之后它在 pck 里面，
而 pck 是只读的** —— 于是「程序升级永不写它」不是一条自律，是装法给的那一件东西。

读出来的是**文件名去掉后缀**当名字：预设不是第二种实体（没有独立的名单，也没有一个自己的名字字段），
所以目录里那一份文件叫什么，它就叫什么。首次运行**不**往用户的 `lifemodes` 里写任何东西（ADR-0005 否掉的那条路）。

## 读法：引擎的 `FileAccess` / `DirAccess`，不是 `System.IO`

**实测结果**（临时目录 + `res://src`，各问一次）：

| 问的东西 | 给的路径 | 实测结果 |
| --- | --- | --- |
| `FileAccess.file_exists` | `C:/Users/…/Temp/keeper-probe-fileaccess/a.txt` | `true` |
| `FileAccess.get_file_as_string` | 同上 | 读出 `hello` |
| `DirAccess.open` + `get_files` | 同上 | 列得出 `["a.txt"]` |
| `DirAccess.open` | `res://src` | 非 null |

**两个坑，都是量出来的：**

1. **斜杠**。`DirAccess.open("C:\\Users\\…")` 在这台机器上列不出来，而症状是「目录不在」——
   一个空画廊，不报任何错。`System.IO.Path.Combine` 给的正是反斜杠那一支，所以自检里那些临时目录
   不换斜杠就会静悄悄变成「一个预设都没有」。改法在 `PresetLifeModes.Path` 一处
   （`dir.Replace('\\', '/')`）。
2. **打包之后 `System.IO` 够不着**。`res://presets/…` 在 pck 里时，`File.ReadAllBytes` 读不到。
   所以读预设**必须**走引擎；读进来的**字节**再交给生活模式那一条现成的路
   （`LifeModeStore.TakeIn(string,string,byte[])`，和 `TakeIn(string,string,string)` 是同一个方法）。

## 「读得通」的定义只有一处

`PresetLifeModes.Why`：讲得通（`JsoncDoc.TryParse`）、读得出一个对象、而且**开头写明了是哪一版格式**
（设计文档 `docs/design/config.md`「第一键是 `schemaVersion`」）。三样都在才叫一份预设。

- 目录**整个不在**自己一档（`Gallery.Missing`），它和「那一份读不通」是两件事，界面上各说各的。
- 读不通的那一份**照样列出来**（名字在、那颗钮灰着、它自己说为什么）—— 一份坏文件说成「一个都没有」
  和一份坏名单说成「你没存过」是同一对假象（`CODING_STANDARDS.md` 第 5 条那一族）。
- 那句「为什么」里**不许有配置文件内部的名字**（设计文档 `docs/design/config.md`「界面上不许出现配置文件内部的名字」），
  所以「开头没写明是哪一版格式」是照人话说的，键名一个字都不进去。自检里对着这一条有判据
  （`Options.ScreenSelfTest` 扫画廊那几行）。

## 出处那一行是从文档里读出来的

`PresetLifeModes.Provenance`：第一个 `{` 之前、顶上那一段连续的 `//` 里的第一句非空的话。
出处住在注释里（`GLOSSARY.md`「预设生活模式」那一条、ADR-0005「考证的取向」），而注释在文档里、
不在界面上 —— 所以界面要显示出处就得**从文档里读出来**，改注释就改了界面上那一行（不是第二份真相）。

读法的边界说清楚：带 `/* */` 的块注释和后面的段落不取（那是格式说明和逐块出处），一行摆不下，
也不该被截半句当出处。

## 「程序永不写它」是怎么量的

三发，都在 `presets-gallery` 那一组里（`Presets.SelfTest`）：

1. **自检自己的那一份预设目录**（`%TEMP%` 里一个用完就删的子目录）：开窗、收一个、撞名、切换、覆盖、
   删掉、导出这一整趟走完，前后各取一次**逐字节**实测结果（文件名 + 长度 + 每一份的内容），
   必须逐字相同。任何一次写进去 —— 哪怕是一个缓存文件 —— 都会红。
2. **模拟一次「升级」**：改掉那一份、再加一份新的（**只动那个临时目录**），然后问三件事：
   用户收进来的那一份**逐字节原样**、它还在名单上、切得回去；而新加的那一份**还是一份预设**
   （`Why` 读得通），且画廊下一次列得出它、列数与目录里的份数对得上。
3. **装在程序里那一个**（`res://presets`）：只**读** —— 列得出、每份都读得通、每份都写了出处、
   名字就是文件名去掉后缀。自检里那一组一个字节都不往里写。

**这一族是减法的另两面**：ADR-0005 否掉「首启直接写进用户 `lifemodes`」的理由是「升级会和用户副本打架
（改过的被盖、没改的分不清谁是谁）」，而上面第二发量的是同一件事的另一半：升级动预设、**不动**副本。

## 自检里那两把尺子，没有第三把

- 「收一个」的递增号、撞名拦阻、备份、逐字节回环：`LifeModeStore.TakeIn` 那一处，判据在
  `presets-gallery` 和 `lifemodes-takein`（后者那把「原样搬」的尺子在这一版**扩展到了预设模板那一种形状**：
  给进来的那一份带一张作息表，而表在活的那一份上也得读得出来）。
- 托盘那一侧**没有**画廊入口，量在 `lifemodes-tray` 那一组，两发各管一件：
  1. **收进来之后托盘只多了「切」的那几行**：临时目录里种出那一份只读目录、把它列出来、再拿那几份名字
     当作「已经收进来的生活模式」递进那份名单，然后比两棵菜单树的**顶层项集**（菜单句柄上真读回来的
     每一项的字、id、灰不灰），必须逐字相同 —— 收进来的那几份在子菜单里是**能递 id 的生活模式**，
     顶层不多出「打开画廊」那一项。
     **为什么不是「目录在 / 不在」两种现场**：托盘压根没有通往那个目录的接缝，那两种现场在托盘这一侧
     不是输入，量它量的是「它什么都没读」的那种相等（2026-10-02 第一版就是那一种，反向验证时
     **没有红**，当场改成这一种）。对照是「换一份名单，子菜单上半真的换了」。
  2. **表上没有任何一行带画廊那一句话**：抓的是「不接数据、光加一行项」那种加法，措辞从
     `Options.LifeModeMenuLabels` 派生（自检里能问的那一处），不手抄一份。
