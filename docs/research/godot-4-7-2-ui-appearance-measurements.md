# Godot 4.7.2 外观这三处不照办：量到的实测结果

日期 2026-09-30。机器：Windows 125% 屏，本机 Godot 4.7.2-stable mono。
实测结果全部来自 `--options-shot` 那一发的实拍帧和它那条「布局」实测结果（`Options.LayoutMeasurement`）。

起因是给设置窗做两套配色（`uiTheme` = `light` / `dark`，默认亮色）时撞到的三处：
**想让引擎照外观的意思想，它有三处不照。** 三处的共同形状是 —— 不报任何错，
自检也全绿，而帧上那一样东西根本没画出来 / 歪着。

---

## 一、`theme_type_variation` 在这一版完全不生效

**问的是**：能不能给一个 `Panel` 标一个变体名（`theme_type_variation = "Card"`），
主题里写一份 `Card/styles/panel`，就只让标了这一颗的节点换样子。

**答的是：不能。** 两种写法都试过，两遍都抓了帧：

1. `.tres` 里只写变体那一份条目，节点上标 `theme_type_variation`；
2. 再加上运行期 `Theme.SetTypeVariation("Card", "Card")` 登记一遍。

两次实测结果一模一样：提示那一行仍是深墨色压在深卡片上、保存钮仍是白钮、卡片退回
引擎默认那套深灰。**帧上没有任何一处变体生效的痕迹。**

**所以现在用的是**：节点上挂 `metadata/role = "Card"`，`Options.PaintRoles()`
从**当前那张主题**里按角色名读值，刷成 per-node 的 `theme_override_*`。
值仍然只有一份（在两张 `.tres` 里），代码和场景里一个色号都没有 ——
变的只是「值怎么落到节点上」这一步。

自检里第 19 条守着这件事：场景里挂的每一个角色名，两张主题都得真的有那个角色
（拼错一个字不会报任何错，只是那一支刷不上，节点退回基础类型那一档）。

## 二、`GridContainer` 是**按子节点次序**排的，不是按名字

**问的是**：一行三格（标签 / 控件 / 单位），没有单位词的那些行补一颗空的单位格，
三列就该共线。

**答的是**：共线的前提是三格**都补上**、而且**次序是 Text → Value → Unit**。
少一格不报错，只是那一行的第三列宽 0；次序错了也不报错，只是**那颗格子顶到了
第 0 列**。

两次都栽在同一个地方，都是先在帧上看出来、再在 `LayoutMeasurement` 上量出来：

| 帧上看到的 | 量到的 |
| --- | --- |
| 带单位词的那几行，标签左缘 34 | `Text[34→552] Value[556→706] Unit[710→756]` |
| 没有单位的那几行，标签左缘 84（**右移 50 像素**） | `Text[84→602] Value[606→756] Unit[34→80]` |

第二行那串 `Unit[34→80]` 就是证据：空单位格被排在行自己的**节点头**上，
于是它成了第 0 列，后面两格整体右移。补的位置必须是 `Value` **之后**。

**另一条要一起记的**：列宽只在**这一行内**取「各格子最大的最小宽」——
每行是一个**各自独立的** `GridContainer`，行与行之间不商量。所以光把格子补齐
还不够，**所有 `Value` 还要同一个固定宽**（现在 150），否则勾选框那一行
（自身最小宽 40）会多吃掉 110 像素。

判据分两半，各归各的地方：形状那一半（三格都在、次序对）是**场景形状**，
在无头自检里问（`Audit` 第 20 条）；位置那一半（标签左缘、控件右缘、单位左缘
是不是同一条线）要等排版跑完，只在 `--options-shot` 那一发量
（`Options.ColumnMeasurement`）。那一发的实测结果**量不到时会说自己量不到** ——
一串 0 拿去比相等是永远相等的那种相等。

## 三、`CheckBox` 的勾和方框是引擎自带的**深色图标**，主题改不了

**问的是**：暗色那张表里，一个没勾的复选框看起来是什么。

**答的是：什么都看不见。** `CheckBox/icons/*` 不设就是引擎默认那张资源，
而那两张是深色的，**主题的 `colors/*` 管不到图标**。

抓帧量到的：

| | 亮色 | 暗色 |
| --- | --- | --- |
| 没勾（压在药丸上） | `#8c8c8c` 压 `#ffffff` —— 看得见 | `#1e2024` 压 `#232830` —— **每通道只差 5 到 8** |
| 勾上（压在药丸上） | 深色 ✓ 压淡绿底 —— 看得见 | 深色 ✓ 压 `#17301f` —— 看不见 |

亮色那版是靠「勾态的底必须浅」硬扛过去的（`CbOn` 的底色取 `accent_soft`），
暗色那版没有「浅底」可退 —— 整张表都是深的，勾和方框一起沉进去。
休息清单那三颗**没有文字**的小方框最惨：它们只有 20 像素，整颗就是那个图标，
于是那一列在暗色下等于**没画**。

**解法**：两张表各带自己的一套图标，`src/checkbox/cb-{on,off,on-dim,off-dim}-<palette>.svg`，
形状只有一份模板（勾 = 一道对勾，没勾 = 一圈方框的描边），**颜色从同一份调色板派生**
（`themetool.py` 里那个 `CHECKBOX_ICONS` 表）。改配色仍然只改调色板一处。

顺带量到的一条**相反**的实测结果：`CheckButton`（开关）的滑块是拿主题的 `font_color`
画的，**改得动**。暗色下窗头「显示高级设置」那颗：底 `#333a44`、滑块 `#929496`。
所以设置行里那些**没有文字**的布尔格（声明里 `Kind=Bool` 的 15 行）改用
`CheckButton`：滑块从左走到右正好把 150 像素的控件列用上，而勾选框那样
把一个 ✓ 孤零零摆在药丸最左边、右边一百多像素全是空的。
**带文字的那些仍然是 `CheckBox`** —— 那一格有字，滑块在文字右边是多余的。

## 四、英文那一面：折行和数词搭配（2026-09-30 深夜）

中文那一侧的帧全对之后，英文那一侧**一次都没被看过**。打开一看，两处坏的和一处读不懂的。

### `autowrap_mode = 1`（WORD）会把英文单词劈成两半

48 颗提示标签写的是 `1`（WORD ——「词放不下就在词中间断开」）。中文看不出来（中文没有词
边界，Godot 本来就在字之间断），英文是**坏的**：

```
each a share of th
e work area
```

「the」被劈开。改成 `2`（WORD_SMART）之后断在词边界上，中文的断法一点没变（帧量过）。
窗头那条 `Error` 标签是 `3`（ARBITRARY）—— 它是**单行**的读不通提示，长了就该在任何地方
断，所以不归这一条管。

**注意 Godot 4 的枚举和文档里常引用的编号对不上**：`0=OFF 1=WORD 2=WORD_SMART 3=ARBITRARY`。
`CODING_STANDARDS.md` 和 `About.tscn` 的注释都把这个编号写反了（写着「1 是 ARBITRARY、
3 是 WORD」），照着那个编号去改会改错方向 —— 那是**写在规矩文件里的假实测结果**，比帧上的错更
贵，因为它会一直误导下一个人。

### 数词和名词的搭配：英文那一侧两处都错

抓帧量到休息流程卡片底下写着「**1 minutes**」，步数那一句写着「**Stretches**」还把 `{n}` 整个
丢了（中文那一条是「共 {n} 段」）。两处都只有英文错 —— 中文没有单复数。

解法是语言表里加 `.one` 那一条 + **一条**规则（数是 1 就取 `<键>.one`），**不按语言分支** ——
规则问的是「数」，不是「现在是哪种语言」（语言运行期会变）。中文那几行 `.one` 的文字和本行
一样（`分钟` / `分钟`），那不是「第二份真相」，是一条语言资源本来就有单复数两栏。

分两族是因为**数住在哪儿不一样**：单位那两条，数是代码打在单位**前面**的（界面上是
「3 seconds」），表里只有那个名词，所以它**不该**带 `{n}`；「共 N 段」那一条数写在表**里面**，
所以它**必须**带 `{n}`。这条判据自己第一版把两族混在一起写，当场自己报自己（`unit.minute`
被说成「漏了 {n}」）。

### 一处**已量、未解释**的实测结果：英文下三列差 5 像素

英文那一侧的「三列」实测结果是「没共线」：12 条行里 8 条控件右缘 706、1 条 705、2 条 701。
中文那一侧是整齐的 706。

三个假设都被实测结果**否掉**了，不要照着任何一个去改：

| 假设 | 量到的 |
| --- | --- |
| 「那一格控件自身的下限比列宽 150 大」 | **全是 150**（12 条都是），而列宽就是 150 |
| 「标签块太长把行撑宽」 | 标签块下限 53–264，离可用的 518 远得很（`flow` 212、`activityTimeoutMin` 264，都在 706 上） |
| 「父级宽度不同」 | **每一行的右缘都是 756** |

能确定的是：**4 条 SpinBox 那几行偏，其余八条（`CheckButton` / `HSlider` /
`ColorPickerButton` / `OptionButton`）都在 706** —— 偏的全是数字框，所以成因和控件**种类**
有关。数字框的下限宽实测结果看不出来（`GetCombinedMinimumSize` 被我们给的 `custom_minimum_size`
盖住了，要看的是 `GetMinimumSize`，那是下一个要量的数）。

所以现在只能说：**≤5 像素、只在英文、只影响数字框那一列右缘**，成因未查。
不要在成因查清之前把阈值放宽 —— 放宽阈值就是把这个实测结果变成恒绿，那正是这一族要防的事。
`ColumnMeasurement` 现在会**逐行报出**（值到哪、这一行到哪、控件下限、标签块下限），
就是为了下一次接着量的时候不用重新猜。
