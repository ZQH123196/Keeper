## 起点那份形状

声明表 48 条（44 条叶子键 + `flows` 表和 `image`/`sound`/`calendar` 三个容器条目），
界面是一扇窗、一根竖滚、九个分区：时间 / 遮罩 / 休息模式 / 休息流程 / 休息清单 / 背景图片 /
提示音 / 桌面日历 / 系统。改之前那张实测帧是 `options-godot-zh.png`（2026-11-08 已移出仓库）：
一屏走完 13 行。

**分区归堆按的是机制不是任务**，三条读得出来的错位：`language` 摆在「遮罩」段里
（改语言与遮罩无关）、`allMonitors` 和 `blockWhenFullscreen` 也在「遮罩」段里
（它们决定什么时候出现）、总开关 `autoFade` 在「系统」段的末尾 —— 整个程序的主开关
躺在整份设置的最底下。

## 分域那一发的实测结果

顶部加一条 Nav（`TabBar` 三格 + `LineEdit` 搜索），域切换只改 `visible`，
**一个分区节点都没搬**（所以自检里驱动这扇窗的四组 `options`/`io`/`flows`/`defaults`
按的还是原来那条路，一处 `GetNode` 都没改）。

三域切完之后在屏幕上真的行数（`IsVisibleInTree` 口径，见下面那条假实测结果）：

| 域 | 分区 | 可见的行 |
| --- | --- | --- |
| 休息提醒 | Time / Fader / flow / Flows / List / Image / Sound | 29 |
| 桌面日历 | Calendar | 13 |
| 系统 | System | 2 |

29 + 13 + 2 = 44，和声明表的叶子键数一致。布局实测结果四发全是「伸出窗口的控件 0 个」，
段那一列最右边到 638、窗口宽 660（横向没有跑出去的）。

## 假实测结果一：问「在不在屏幕上」不能问那一行自己的 `Visible`

分区被收掉时，**分区里每一行自己的 `Visible` 仍然是 `true`** —— 引擎的 `Visible`
只管自己那一层，不问祖先。所以数「可见的行」如果走 `row.Visible`，切到日历域之后
仍然报 44，看起来像「域切换没生效」。

问的是 `IsVisibleInTree()`。同一发还顺带暴露一个判据写错的地方：拿「全部 44 行」当
搜索那条的基线，问的其实是「域切换生效了吗」，那是另一条判据的事。基线该是**当前域
在场的行数**。

**这一条拦住的是测量程序，不是产品** —— 但它拦掉的那一版同样会拦掉人：日志里写着
「可见的行 44」而画面上只有 13 行，谁读到都会先去怀疑产品。

## 假实测结果二：自检里那扇窗自己的日志，默认被空委托吞掉

`Options.Log` 的默认值是空委托 `(_, _) => { }`。自检里 `NavSelfTest` 开的那扇窗
没接它，于是窗自己的「可见性：域 N 搜索 '' → 可见的行 44」一行都不出来 ——
**实测结果一条都没有**，只剩「搜 opacity，音量那一行还在」这一句结论。

查那一发查了半轮：推理了四五个错的方向（`LineEdit.Text` 赋值不触发信号、旧 DLL 冒充
通过、`TabBar.TabChanged` 参数类型、异常被吞），每一发都能自圆其说，却一个实测结果也没有。
`CODING_STANDARDS.md` 第 5 条那条（实测结果说不通先怀疑测量程序）在这一发上不是「记得」，是
**唯一出路**：接一个收集器，实测结果立刻就出来了。

接收集器时自己又踩了一次同类坑：**收全部日志、限 80 条**，结果开窗那十几行就把额度
用光，真正要看的搜索那几发一条没留下 —— 收集器自己成了那个假阴性。改成只收含
「可见性」的那几行。

## 那个真 bug：反推分区名多取了一层

`SectionOf` 从节点路径反推这一行属于哪个分区（`…/Form/<分区>/<行>`）。它多取了一层
`GetParent()`，于是每一行都算成 `Form`，`belongs` 恒为 false ——
**两层都不动，搜索永远筛不掉任何一行**。

自检里那条对照判据（搜 `opacity` 时「音量」那一行不该在）当场咬住。反向验：把那个
`GetParent()` 塞回去，立刻报同一条、退出码 1。

## 假实测结果三：实测结果说「不通」时先看自己的测量程序 — 自检里开了窗但没接线

同一个 `NavSelfTest` 里，先接了 `Log` 收集器、看到「可见性」实测结果、又反向验证过它能失败，
前后都对上了。但搜「音量」时画面上还挂着「时间」「遮罩」两个**空标题** ——
分区被筛空了，标题没跟着收。

改完（`drop` 时 `section.Visible = false`）再抓帧，空标题确实没了。这条不是假实测结果，
是真缺陷，只是要靠「抓实拍帧 + 看」才看得见，自检里那条判据问的是行不是标题。

## 搜索匹配四栏，中英文各占一半

匹配 `SettingDecl.Key`（英文键名）、标签（`Tr(key)`，中文）、提示（声明的注释）、
单位（`Tr(key + ".unit")`）。**键名参与匹配**是必须的：只按中文标签筛，敲 `opacity`
找不到「最大不透明度」那一行；只按英文键名筛，敲「音量」找不到音量那一行。实测两个
方向各中一次（`nav` 那一组里各有一条判据）。

搜到东西时，**一个纯设置行的分区被筛空了就连标题一起收掉**；而休息流程（步编辑器）、
清单、「走哪一条」那行下拉那三区有搜索筛不掉的内容，留在场上（`KeepsOwnContent`）。

## TabBar 在白底上要配两个背景 stylebox

`Options.tscn` 的 Theme 是自建的白底。TabBar 引擎默认是深色那一套，不配背景的话
页签是深灰底块压在白底上。配了 `tab_selected`（浅绿底 + 绿下划线）和
`tab_unselected`（浅灰底），并给两者加左右 12 像素内边距 —— 不加的话三个页签的字
会连成一片（第一版抓出来就是「桌面日历系统」）。

选中态第一版做成了整块实心绿底 + 白字（`bg_color` 给了不透明绿），不是想要的
「深绿字 + 下划线」；改成 `bg_color` 半透明 + `border_width_bottom = 2`。

## 测量程序那一发扩了两个旗子

`--options-shot <路径>` 加了 `--domain <第几格>`、`--search <词>` 和 `--advanced`（不跟值）。
原来那一发滚到休息流程那一区（`RevealFlows`），现在：显式给了 `--domain` 就照给的来
（域 0 也不例外 —— 那一格的正脸正是原来抓不到的那一屏），没给才走原来那条。`--more`
走的是按钮自己的 `Toggled`，和真点出来的是同一条接线 —— 直接改 `_advanced` 只能改
字段，按钮的按下状态和那颗钮上的数都不会跟着动。

## 第二轮：常规 / 高级

### 实测结果

| 那一发 | 可见的行 |
| --- | --- |
| 域 0 开窗（默认收起高级） | 11 |
| 域 0 全展开（5 颗开关） | 29 |
| 域 0 搜「停留」 | 1 |

44 条叶子键里 16 条常规、28 条高级。域 0 常规 11、域 0 高级 18，全展开 11 + 18 = 29
（条数以 `--check` 那跑印出来的为准，这里记的是那一跑的形状）。实拍帧是
`options-common-zh.png`、`options-advanced-zh.png`、
`options-search-advanced-zh.png`（2026-11-08 已移出仓库），三发布局实测结果都是「伸出窗口的控件 0 个」。

### 假实测结果四：判据的次序也是判据的一部分

档位那一整块（默认只露常规 / 展开后全回来 / 搜索无视档位）一开始插在「清空搜索」**之前**。
实测结果是两条问题：搜「停留」找不到高级键，以及「没搜的时候可见 0 行」。

第二条才是要点：那时搜索框里还留着上一个词，Time 区被搜成空、**整区连标题一起收掉**
（`drop` 那一支），于是后面那条问「默认露几行」的判据量的其实是搜索。
判据各自都对，**串起来的次序**是错的 —— 这是第一轮那条「一行都没剩下的分区连标题一起
收掉」规则的直接后果。

### 假实测结果五：判据里手写死的搜索词

改完次序，搜「停留」那条还是红的。语言表里 `minBreakMs` 的标签是「停留多久算真正休息」，
含「停留」—— 可自检里那扇窗的标签压根不是那句（见下），量的是「没人搜的词」。

**同一个病根的两种长相**：判据自己存了一份会腐烂的副本。档位标签是第一种，搜索词是
第二种。现在搜索词**从那一行自己的标签上现取**（`Options.LabelOf`），并配一条前置判据
问「它有没有在标签栏命中自己」—— 没命中就明说那一发量的不是搜索，先怀疑测量程序。
旁证：三条消息里手抄的「标签名」也一并换成键名，报错时指着 `minBreakMs` 而不是指着
一句可能早就改掉的中文。

### 假实测结果六：自检里那扇窗没装语言表，于是一条判据一直在量错的东西

`Lang.Apply` **只在 `App.cs` 里调**（两处），自检的 `Probe.cs` 那一侧从来不装。于是自检里
`Tr(键)` 原样吐回键名，标签那一栏量到的是 `sound.volume` 而不是「音量」。

后果不是哪条判据红了，是搜「音量」那条**一直是绿的，量的却不是标签** —— 它中的是
**提示**那一栏（提示直接灌 `Decl.CommentZh`，不过 `Tr`）。所以第一轮写下的
「中文标签该参与匹配」这个结论当时**并没有被证到**。

`NavSelfTest` 现在开窗前先 `Lang.Apply(state.Current.Language)`，表本身有问题就当场
返回；再加一条前置判据问「这扇窗里 `sound.volume` 的标签是翻好的『音量』还是键名」。
反向验：不装表 → 3 条问题（含「搜『音量』中的是提示那一栏，不是标签栏」），立刻红。

### 假实测结果七：功能做完了不等于东西能看

第一版的「每区一颗『高级设置 · N』」功能全对、自检全绿，**像素是不能看的**：那一颗是
`flat = true` 的按钮 —— 没有三角、没有描边、没有底色，字号字色和上面的设置行一模一样，
缩在分区左下角，看上去就是一行漏排版的文字；同一扇窗里重复五次。他只看了一眼就问
「怎么可以这样烂的设计」。

这一条不属于「实测结果」的失败 —— 自检从头到尾没有报错过，它量的是**功能**（默认收起、勾上
全回来、搜索无视档位），而「这东西长得像不像一个控件」不在任何一条判据里。所以它得
单独立一条规矩：控件的样子和它的功能一样要当回事，**做完了要拍帧看像素**，不要只看自检全绿。
（实拍帧那一发本来就在，问题是拍完只用来验布局 ——「伸出窗口的控件 0 个」—— 没用来
看它像不像个东西。）

改法是**换摆法而不是修控件**：窗头一颗「显示高级设置」开关，一处管全窗，五个 `More`
节点从场景里删掉，窗里不再有任何折叠行。档位、收起、搜索豁免三样都留着。

### 新判据的反向验

改了产品、自检必须红。这一轮验了七处：

| 弄坏的地方 | 自检报出来什么 |
| --- | --- |
| `tierOk` 去掉 `\|\| _query.Length > 0` | 搜高级键那行自己的标签，它还是不在屏幕上 |
| 勾上开关时 `Toggled` 里不让它生效 | 勾上「显示高级设置」，`minBreakMs` 那一行还是没有（+2 条） |
| 勾上开关时 `IsAdvanced` 恒为 false | 开窗默认该收起高级设置，`minBreakMs` 那一行还在屏幕上 |
| 声明里 `tier: "advnaced"` 拼错 | `options` 组：声明里的档位 'advnaced' 不认识（只有 common / advanced） |
| `tierOk` 去掉 `\|\| _showAdvanced` | 勾上那颗开关，高级一条都没回来（3 条） |
| 让它**只管休息那一侧**（`&& SectionOf != "Calendar"`） | 勾上后切到桌面日历，高级的行还是没有 —— 那颗开关只管了半个窗 |
| 搜索时不去按那颗开关 | 搜索时「显示高级设置」那颗开关还能按 |

倒数第二条是换成全局开关之后**新增**的断言：每区一颗时它天然成立，换成一颗之后得单独
咬住「一处管全窗」这件事 —— 一颗开关只接了本域，是最自然的一种写坏。

第三条顺带证明了默认 `common` 的取舍：拼错的那一种让那一行**跑到明处**（当成常规显示），
而不是静默藏起来 —— 自检会抓到，且症状是「多了一行」不是「少了一行」。

## 第三轮：分区之间要看得见（2026-09-30）

> **这一轮关于分割线的结论已经被第四轮推翻**（同一天晚些时候）：`Rule`（`HSeparator`）和
> `ApplyRules`（顶上那一道按次序收放）整个退休，分区改成**一张张卡片**
> （`PanelContainer` + `metadata/role="Card"` + 卡片里一竖排 `Body`），区与区之间靠卡片
> 自己的底色和描边分开，不再有分割线。下面那些实测结果**当时是真的**（`StyleBoxLine` 那一道
> 落在白底上几乎看不见是真的），但**「现在长什么样」和「新判据」那两张表都已经不是现状** ——
> 判据换成了卡片形状那几条，实测结果在 `godot-4-7-2-ui-appearance-measurements.md`，
> 形状那一半的量法（三列共线）在同一份的第二节。

他看的是实拍帧，说的是三件事：番茄钟要自己一区、区与区之间要分割线、右边和底下那两根
「难看的进度条」。前两件是缺，第三件里**一件是缺、一件是量错了意图**。

### 底下那根：写的是「一直显示」，不是「关掉」

`Options.tscn` 的 `Scroll` 那一行写着 `horizontal_scroll_mode = 2`。查引擎文档
`ScrollContainer.ScrollMode`：**0 = DISABLED、1 = AUTO、2 = SHOW_ALWAYS、3 = SHOW_NEVER、
4 = RESERVE、5 = MAXIMIZE_FIRST**。所以那个 2 是「永远显示横条」—— 它一直挂在窗底，
而它长得确实像一条进度条。内容宽度跟着窗宽走（Form 那一列 `size_flags_horizontal = 3`），
横向本来就没有可滚的余地。改成 0 之后那根条没了，`nav` 那一组里
`GetHScrollBar().IsVisibleInTree()` 读出 `False`。

**这一条是「记错的常量」那一族**：写的人（我）把「关掉」记成了 2，而 2 的字面意思恰好
是相反的那一档。这类错在构建和自检里都不会响，只有像素能看见。

### 右边那根：`StyleBoxEmpty` 把条摆成了宽 0

`Options.tscn` 那个自建 Theme 原来没有竖滚的条目，于是右边那根是引擎默认那套深色
轨道 + 深色抓手，压在白底上像一根黑线（改之前的帧 `options-common-zh.png` 右边那一道）。

第一版配的是「透明轨道（`StyleBoxEmpty`）+ 浅灰抓手（`StyleBoxFlat`，左右各留 7）」。
抓帧一看：**右边那根整个不见了**。

在测量程序的布局实测结果里加了一条（`Options.ScrollMeasurement`，走 `LayoutMeasurement` 末尾）：

| 那一发 | 竖滚在屏 | 竖滚宽 | 抓手主题最小宽 |
| --- | --- | --- | --- |
| 轨道 = `StyleBoxEmpty`，抓手边距 7 | True | **0** | 6 |
| 轨道 = `StyleBoxEmpty`，抓手边距 3 | True | **0** | 6 |
| 轨道 = 透明 `StyleBoxFlat`，左右各 5 | True | 10 | 6 |

**`ScrollContainer` 是拿竖滚的最小宽度去摆它的**，而最小宽度取自 `scroll` 那个 stylebox ——
`StyleBoxEmpty` 的最小尺寸是 0，于是整根条被摆成宽 0，一根都不画。抓手自己的
content_margin（`GetMinimumSize()` 读出来是 6）管的是抓手那一截，不参与这个宽度。
所以轨道要「看不见」而不是「不存在」：透明背景的 `StyleBoxFlat` + 左右各 5 的内边距。

这一条是**假实测结果那一族的又一次**：在屏 `True`（节点在树上）而像素上没有 —— 问「在不在」
和「画没画出来」是两件事，和 `desktop-layer-and-window-measurements.md` 里
`IsWindowVisible` 那一族同一个病根。**实测结果要多问一层：一个控件在树上，不等于它画出来了。**

### 分割线和小标题

每一区现在是 `Rule`（`HSeparator`）/ `Title`（`Label`）/ 各行。小标题 13 号、灰
（`Color(0.42, 0.44, 0.47)`，和页签未选中那一句同一个色），行名 15 号、深字 ——
差一档才分得出「这是个头」和「这是一条设置」。分割线是 `StyleBoxLine` 1 像素浅灰
（`Color(0.855, 0.867, 0.882)`）；引擎默认那一条是深色主题里的浅灰，落在白底上几乎看不见
—— 抬头下面那道 `Rule` 一直摆着，一直读不出来。

`HSeparator/constants/separation = 8`：这一项是**上下留白，不是间距**（文档原话
「affects the drawing of the separator, not the layout」），所以线上下的白是从分割线
自己的高度里出的，不靠改各区的 `separation`。

**顶上那一道不摆**：域一变顶上那一区就换人（域 0 是「时间」、域 1 是「桌面日历」），
所以它收在运行期（`Options.ApplyRules`），按 **Form 里的实际次序**扫一遍 —— 不按
`SectionTitles` 的次序，那是「节点名 → 标题」那张表，形状在场景里。

### 番茄钟自己一区，和它带来的那条判据

`pomodoro.workMin` 原来在「时间」那一区里，而且声明成 `advanced`。搬出去单独一区之后，
默认视图下（高级收着）那一区**只剩一个光秃秃的小标题** —— 正是
「假实测结果三」那一类（空标题）。所以它挪回 `common`（声明表里一处，界面不存这个状态），
自检里加了两条对着这件事的判据：

- **Audit 16**：每一区都得有 `Rule` 和 `Title`，且 `Rule` 在前。
- **Audit 17**：每一区至少要有一条**常规**行，除非它在 `KeepsOwnContent` 里
  （那三区自带内容，本来就不靠设置行）。

17 那条的由来值得记：它是把「假实测结果三」那条**运行期**规则（搜到东西时空区连标题一起收）
**搬到静态那一侧**。运行期只管搜索筛空的那一种，默认视图下「一条常规行都没有」从来没被
问过 —— 而后者是更常见的那一种。

### 新判据的反向验

| 弄坏的地方 | 自检报出来什么（那一发的原话） |
| --- | --- |
| 删掉日历那一区的 `Rule` | `Calendar：这一区没有分割线（Rule 那个 HSeparator）` |
| `pomodoro.workMin` 写回 `tier: "advanced"` | `Pomodoro：这一区一条常规行都没有，默认视图下它只有一个光标题 —— 把其中一条声明的 tier 挪到 common` |
| 横向滚轮写回 2 | `横向滚轮是 SHOW_ALWAYS，窗底会一直挂着一根横条 —— 要的是 0（DISABLED）`（`options` 组）+ `窗底挂着一根横向滚条 —— 内容宽度跟着窗宽走，横向没有可滚的余地`（`nav` 组，运行期那一发） |

### 编辑器存场景会删掉 `;` 注释

这一轮撞上的：Godot 编辑器（4.7.2）存过一次 `Options.tscn` 之后，**顶上那段 `;` 开头的
说明整块没了**（所以今天那个文件顶上已经没有它了），同时每个节点上多了 `unique_id=`、
`load_steps` 不再写。同一目录下
`About.tscn` 的头注释还在 —— 因为那次没存它。

后果有两层：一是手改场景时编辑器会把改动冲掉（这一轮改坏了一次才看见），二是
**场景的长说明挂在会被编辑器删的地方**。头注释已经补回去（连同这一条警告），
但要记住：`Options.tscn` 里凡是「为什么这么摆」的文字，都可能被下一次编辑器保存抹掉；
真正不许丢的那部分取向在 `Options.cs` 的注释和 ADR-0001 里。
