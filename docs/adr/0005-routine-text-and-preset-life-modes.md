# 作息表、遮罩文字与预设生活模式：让 app 演一种过法

2026-10-02 所有者定夺（起因：要一批「市面上各种生活模式」的预设 —— 嘉靖、村上春树、机构指南……相当于角色扮演）。产品行为在契约；那一族的形状在 `docs/design/daily-routine.md` 与 `docs/design/preset-life-mode.md`，术语在 `GLOSSARY.md`「作息与预设」那一节；这张卡只装取向、被否的路和代价。

## 作息表是第二条按现实时间走的路，不是闹钟

**取向**：作息表和番茄钟并列，同属按现实时间走的那一族；连续输入那条触发照旧是另一族。作息表是「一天的框」，番茄钟是「跑到停为止的循环」—— 两种形状，互不吞并。

**否掉的：把作息表做成番茄钟的推广**（番茄钟改写成作息表的一种特例）。循环没有到点的概念、日框没有轮的概念，硬统一会让两边各带一半自己不读的键 —— 那是把接口做宽不是做深。

**否掉的：块到点用系统通知 / 闹铃。** 那是「新增一种打断」，整个产品命题（改光，不改流程）会翻。**代价认下来：Keeper 叫不醒人** —— 凌晨四点机器在睡时什么都不会发生；作息表是机器醒着时的引导。「像村上一样四点起床」这半个角色扮演，在这台机器上只能演成「你四点若在屏幕前，光会告诉你现在该晨间写作」。真要叫醒是另一种产品哲学，契约 Out of Scope 里点名了，要做得单独一次定夺。

**否掉的：为作息表发明第二种弹窗。** 块到点那一次抬遮罩走的就是休息流程那一行 —— 换步不碰窗、斜坡、挥散，整套复用；作息表只新增「什么时候抬、抬哪一行」。到点那一次抬**不进休息记录 / 足迹 / 健康度**：进了就会把「提示你换块」算成「你休息过」，健康度会撒谎。

**「睡眠」这个种类的静默是种类语义，不是默认政策。** 所有者的原话：「你要为什么要管默认？默认值跟作息模式有什么关系？作息模式有需要自己会去覆盖默认值的。」于是：种类里只有**睡眠**带行为语义（标着它的块里一切触发都不抬遮罩），其余种类只是标签；块内行为逐块显式写，默认值由声明表给，预设生活模式各写各的值。**代价认下来**：「专注块里不被输入提醒打碎」必须显式写键，模板里漏写角色扮演就碎 —— 这一条落在预设内容那张工单的验收项里，不靠种类兜底。

## 遮罩文字正本清源：自带的就显示，Keeper 仍不劝人

**翻案。**「遮罩上故意没有文案」是早先的产品意图，2026-10-02 被所有者正本清源，原话：「任意编辑，本来的设计就是自由编辑的，相当于有自由编辑文字区和一个 todolist 区（可选），『故意没有文案』我不清楚是谁搞出来的 bug，如果现在办不到，那就是时候正本清源了。」

**翻案后的界线只有一条**：遮罩显示**状态实测结果**（时钟 / 足迹 / 健康度 / 当前时间块名）和**步自己带的内容**（`text` 自由文字、`checklist` 清单），而 **Keeper 自己不写一句劝说的话**。当初「没有文案」防的是弹窗说教，不是「遮罩上有字」—— 翻案之后防的还是前者。

**否掉的：保持无文案，只用颜色与节奏演角色。** 表达力不够（「晨间写作」和「斋居修道」压成同一种绿就分不出来了），所有者否。

**代价**：自检里凡有断言 content 枚举只有四种、或断言遮罩上没有文案的判据，要在遮罩文字那张工单里**反向修掉并留实测结果** —— 不许悄悄放宽一条判据（契约 Testing Decisions 里写明了这条纪律）。

**`text` 与 `block` 分开**：`text` 是步的静态字段（住休息流程），`block` 是 content 里唯一动态的成员（当前时间块的名字，作息表替它算；没有作息表或不在块里就空着）。字不在两处存 —— 块名只有作息表一份真相。

## 一次休息不再换步：中间放文字，侧面放清单

2026-10-06 所有者定夺，原话：「怎么是 todo 清单？我要的是 todo 清单归 todo 清单，语录归语录。休息时应该在中间显示语录时间，侧面显示 todolist。而且不能出现切换！发现休息居然会发生切换到 todo 清单这回事！」

**取向**：`todoList` 那条出厂休息流程从两步合成一步。中间那一族（时钟、休息足迹、健康度、时间块名、那一步自带的文字）和侧面那一条清单**同屏**，两处之间不换步。清单摆侧面、中间摆文字，是布局上的分工，不是两件事。

**为什么「不能出现切换」是硬要求**：换步不碰窗（契约原有那一条），所以换步读出来是「屏幕上那批东西忽然换了一批」—— 一次休息被切成两件事，看的人不知道自己还在同一次休息里。**步这个机制留着**（用户能自定义多步休息流程，预设生活模式里那些模板就靠它），只是出厂那一条不再用它做「清单接力」。

**否掉的：默认那条保留两步，靠换步把清单换上来。** 那是 2026-10-02 之前那一版的做法，就是被否掉的「切换到 todo 清单」。

**代价**：勾清单从「落定之后那一段」变成「遮罩完全浮现之后」，而「落定」这个时刻第一次成了**收鼠标的时刻**（见下）。实测结果在 `Fader` 的 `Settle` 与 `Enter` 那两处注释里。

**收鼠标的时刻从「进步那一刻」改成「遮罩完全浮现之后」**：合成一步之后这两件事变成了同一时刻，而遮罩落下的那一刻人往往还在打字 —— 按原来那套在进步时收鼠标，抢走的就是正在打字的那只手。所有者定夺的原话是「没有前 3 秒这一说！在遮罩完全浮现后可勾」。契约级的一条：淡入途中不碰鼠标，鼠标归遮罩的时刻是**落定**，不是**举起来**。

**设置窗：按「最常改的放上面」重排，遮罩整张收进高级**。所有者定夺原话：「按照人类的使用习惯，最常改的应该放在上面，背景和提示音也太低下了」「遮罩这应该属于高级设置，没有人天天改遮罩颜色的」。「休息提醒」那一格的次序因此是 时间 → 休息清单 → 番茄钟 → 背景图片 → 提示音 → 勿扰；遮罩那一卡的每一行都成了 `advanced`，默认视图下**连标题一起收掉**（不是只收行 —— 那会剩一个光秃秃的标题挂在屏幕上，像坏了）。

**代价**：遮罩那一卡默认视图下点不到，要勾窗头那颗「显示高级设置」。这是有意的，判据钉在 `Options.NavSelfTest`（那组开窗量可见性），静态那一半在 `Options.Audit`。

## 预设生活模式不是第二种实体

**取向**：预设 = 一份完整配置文档 + 一个只读目录 + 注释即考证。「收一个」走现成的导入路径，于是递增号、撞名拦阻、备份、逐字节回环那一整套规矩全部白送。

**否掉的：独立的预设格式 / 实体。** 会丢上面整套规矩，而且「半个生活模式是不存在的」那句会开始存在例外。

**否掉的：首启直接写进用户 `lifemodes`。** 升级会和用户副本打架（改过的被盖、没改的分不清谁是谁），「敢切」会变成「敢升级」。预设永远只读，收进来才算自己的。

**考证的取向**：注释是出处的载体，逐块写「这个数来自哪条来源 / 哪里是演绎」；研究文档一份一题落 `docs/research/`。名单的两条界线：**嘉靖**作息无硬史料，模板里明写演绎重构及其依据，不假装考证；**周恩来**只取「自律短憩」面向 —— 长工时复刻和这个产品存在的理由相反，那条不做。
