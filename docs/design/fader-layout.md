# 遮罩的布局

遮罩那一屏的形状：**每一步自己那一份布局**。这一份只写布局的形状与机制。
产品行为在契约 `.scratch/keeper-contract/spec.md`「行为不变量」那一节。

## 遮罩的布局是每一步自己那一份

不挂在休息流程上，也不全局共用。理由：「显示什么」今天已经是每一步的事，
布局跟着走才是一件事一个主人。

代价是摆三步要摆三次 —— 编辑器里给一颗「照抄上一步的布局」把这件事压成一次。

## 六种控件

从声明表现读。**文字和图不限个数**，摆几张摆几步都是；**其余每种最多一个** ——
两个时钟没有意义（第二个永远显示同一个时刻），清单是一份记录不是几份，
那颗钮是一个收尾动作。

| 控件 | 装的是什么 |
| --- | --- |
| 时钟 | 当前时刻 |
| 倒计时 | 这一步还剩 m:ss |
| 休息清单 | 那一列能勾的行 |
| 时间块名 | 按作息表现在所处的时间块的名字（布局里唯一动态的一个） |
| 「提前结束休息」那颗钮 | 收尾动作 |
| 文字 | 人自己写的那一段话 |
| 图 | 一个路径，外加它那五种摆法之一（填满、适应、拉伸、平铺、居中） |

**不加新的种类。** 每加一种，声明表加一行、布局加一个分支、编辑器加一颗钮、
遮罩加一段绘制，图还要挑一种摆法。要加是另一次定夺。

那五种摆法原先是整屏背景的摆法，2026-10-06 之后那个框就是它们的边界，
「平铺」是在框里平铺。

## 六种都能改大小，都能删

用户故事说的是「有这颗钮」，不是「永远摆在这一屏的右下角」。删掉就是少一样。
编辑器里给一颗「回到默认布局」把它们全放回原位。

**不做撤销**：布局是一份文档不是一串动作，撤起来比看起来贵。

## 位置和大小存成屏宽屏高的份额，不是像素

存像素的话，换一块分辨率不同的屏，每一块屏上摆的位置都是错的。

链是**「屏的份额 → 框 → 字号 → 地板」**：位置和大小是屏宽屏高的份额，
字号是控件那个框的一个份额，再加一根跟随系统 DPI 的地板 —— 框太小，字会小到读不出来。
那根地板和日历那份是同一根。

## 允许重叠，重叠时后来摆的在上

用户摆的控件**允许重叠**，重叠时**后来摆的在上**。编辑器里给「往前一层」「往后一层」两颗钮
（见 `layout-editor.md`）。

## 默认布局就是今天这一屏原样

中间一族按今天的次序和字号，清单和那颗钮在今天的位置，图铺满整屏。
第一次运行和「回到默认布局」摆的都是这一份。

## 老配置照今天的排法自动生成一份布局

名字还认得的成员照原样变成控件，那一步自带的文字变成一个文字控件，
配置里那格图变成一个铺满整屏的图控件；写着但不画的那两个成员不变成控件。
`content` 和 `text` **从此不再是权威**，只是被读这一次 —— 用户改过布局之后它们是
「陌生的键」，零代价。`schemaVersion` 要动。

选这条路而不是「老配置退回默认」，理由是那几个名字今天还认得，翻译是几行代码的事，
用户手改过的东西不该静悄悄消失。

## 两条不许破

控件不许**出屏**、不许**是零**。判据在 `src/StepLayout.cs`。
