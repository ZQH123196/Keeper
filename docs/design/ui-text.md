# 界面文字的那一张表

Keeper 自己那些文字的来源。这一份只写边界。
产品行为在契约 `.scratch/keeper-contract/spec.md`「行为不变量」那一节。

## 语言的默认是中文

界面里每一条文字都出自**同一张表**。编译期那道保证由构建里跑的一条无头自取代 ——
**缺 zh 或 en 就非零退出**。

## 「同一张表」管的是哪一部分

2026-10-02 所有者定夺，把这一句说准而不是说松。

**管的是 Keeper 自己的措辞** —— 标签、按钮、提示、托盘那些项。

**不包含文档里的数据**：用户自己给生活模式起的名字、休息流程的名字、
**预设生活模式自带的块名与遮罩上那一段自由文字** —— 这些是**摆出来的那一栏本身**，
原样显示，不进语言表。

理由：它们本来就只有一个样子，而语言表那种「一处两份」的保证对它们没有意义 ——
一个用户把自己的生活模式叫「写作」，他在英文界面下看到的也还是「写作」，
而那个词不是我们写的。

**代价认下来**：收一份中文的预设生活模式，在英文界面下它的块名仍是中文。
这是这一版的行为，不是漏项。

## 托盘那一行是「语言表 + 数据」拼成的一句

exe 名、完整路径当**数据**原样拼，不进语言表、不带可选值。
