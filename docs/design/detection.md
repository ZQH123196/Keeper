# 检测那一族

检测模块的边界。这一份只写边界与形状。
产品行为在契约 `.scratch/keeper-contract/spec.md`「行为不变量」那一节；
取向与被否的路在 `docs/adr/0006-detection-module-boundary.md`。

## 一句话边界

**检测只出实测结果，政策在消费方。**

## 检测回答事实

三问：**输入三问**（闲置 / 连续 / 持续）、**独占全屏吗**、**前台应用是谁**。

**怎么用这些实测结果是消费方的事** —— 同一个独占全屏实测结果底下，
番茄钟「让开就抬」、块到点「错过不补」、自动淡入「不记账也不补」，
三条政策互不相同。检测**不合并**它们，也不输出「现在能不能打扰」。

## 取数

搭现有 0.2 秒那一发的轮询底盘（App 那一侧），**不发事件、不开线程**。

前台应用按**可执行文件名**认：跨安装位置稳、人读得懂；
同名冲突认下来（名单是用户自己写的）。

输入检测和独占全屏是既有两件搬进来的；`Input` 那三问的接口**原样保留** ——
假时钟那一套自检靠它推。

## 输入三问的算术

三个数各有一条判定，都在这一族里：

- **闲置**（`IdleMs`）：离上一次输入过了多久。
- **连续**（`ContinuousMs`）：两个输入之间隔太久，这一段就从头再攒。
  那个门槛是 `Activity.StreakGapMs`（60 秒，**所有者定的，不动**）。
  **2026-10-21 之后它不再参与倒计时和触发** —— 它只答一件事：
  **人是不是离开了**（离开够久就把休息延迟那个欠账清零，下一次回到序列的第一格），
  而且**只在挥散过之后才问**（没挥散过就没有欠账，也就没有「离开」这一说）。
- **持续**（`BusyMs`）：静默超过 1 秒就不算「你回来了」，所以只来一下输入
  永远攒不成一次挥散。

**这一族只出这三个数。** 攒够没有、该不该淡入，是消费方（Scheduler）的事。

## 倒计时和触发按现实时间走

**2026-10-21 所有者定夺：删掉「连续输入」跟倒计时的任何关联。**

「这一段已经走了多久」由 `Scheduler.ElapsedMs` 答，到点就提醒。
中间停手多久都不影响它 —— 以前停手超过 60 秒就要从头再攒，
于是 25 分钟那条线在正常使用下几乎永远攒不到
（本机实测：桌面那份导出版连跑 5 小时，遮罩零次抬起；读数在
[`../research/continuous-streak-gap.md`](../research/continuous-streak-gap.md)）。

**这一段的起点什么时候归零**：

| 情形 | 归零 |
| --- | --- |
| 真歇过（走完、或人走开够久） | 是 |
| 「序列取完、这一轮作罢」 | 是 |
| 取消（挥散 / 提前结束休息） | **否** —— 往后推的是下一次淡入的时刻 |
| 到点那一次（块到点） | 否 —— 它不是休息 |

「取消不清」沿用 2026-10-13 定的取向：清了就把「往后推一格」顶成空话。

## Scheduler 那一侧

Scheduler 面对的是一个每帧组装的聚合（三问 + 独占全屏 + 前台应用 + 勿扰中，带原因），
类型住在 Scheduler 旁边；**政策（休息延迟、让位、静默）仍全在 Scheduler**。
App 负责拼它：实测结果来自检测，勿扰位来自勿扰。

## 那一族四件事：先量，再钉机制

2026-10-07 所有者定（之前这一族整个挂在 Out of Scope，10-04 定的，10-07 撤回）。
四件里有三件是「多接一条读数」，一件是「多一个消费方」。**边界不因为数量变**。

**四条都先出本机实测结果，量之前不钉机制。** 结果按题落进
`docs/research/detection-module-api-survey.md` 对应各节，机制定了再改这一节。
**不许先写实现再回头找实测结果。**

### 暂停正在放的东西

用户故事 97，工单 18。候选三条路：`WM_APPCOMMAND`（发给谁）、
`SendInput` 虚拟媒体键（UIPI 边界）、`GSMTCS`（`TryPauseAsync` + `PlaybackStatus`）；
`NtSuspendProcess` 已判死。

**暂停名单是勿扰名单之外的另一张**，不合并 —— 一个是「别来烦我」，一个是「别出声音」，
是两件事。**休息走完要不要恢复播放没定。**

### 「智能」勿扰

用户故事 98，工单 19。候选形状两条：按更多实测结果自动组合静默，或学习用户挥散模式。
**「智能」指什么没定**，自动条件的边界、用户能不能否决，也都没问过。

**这一条不许拿「智能」两个字先当名字用** —— 「模式」那三回撞词是教训。

### 读系统勿扰（Focus Assist）

用户故事 99，工单 20。官方查询 API **不存在**。社区路线是逆向的 WNF 状态或注册表，
跨版本不稳（实测证据：Win11 勿扰连 `QUNS` 都不反映）。

**当独立开关测，不焊死主路径** —— 「读数对不上要查机制」那种账，这一版认。

### 前台变化走事件

用户故事 100，工单 21。`EVENT_SYSTEM_FOREGROUND` 专线程钩子
（`GetMessage` 循环、`GCHandle` 钉委托），和现有 0.2 秒轮询对账。

已知坑都带出处：迟到、最小化双发、锁屏解锁后同类钩子失灵。
**纯事件 / 双路对账 / 维持纯轮询，三条没定。**
