# 布局编辑器

摆布局的那一扇窗。这一份只写它的形状与机制。布局本身的形状在 `fader-layout.md`。

## 单独一扇窗，和屏差不多大

画布要按屏的比例显示 —— 设置窗再大也不到全屏，在一块小画布上拖一个控件，
差十来个像素，到屏上就是差一大截。所见即所得。

程序里从此有五扇窗：设置窗、编辑器、遮罩、点击窗、桌面日历。

## 画布是真控件，自绘的只有上面那一层

「用真控件还是自绘」那个二选一本身不对。画布是真 `Control`、子控件是真 `Panel`，
控件的焦点、主题、命中全走引擎；`_draw` 只画刻度线和手柄那一层。

**引擎重排不会把自绘那一层抹掉**（挪子控件、换画布尺寸、不主动重画，四种读数下都在）。

**拖动过程中那一档要自己 `QueueRedraw`** —— 量到的是「不主动重画时上一次画的还在」，
不是「位置自动跟着变」。读数在 `docs/research/godot-drag-and-snap.md`。

## 拖放走引擎的虚函数，刻度线和手柄自己算自己画

引擎给的：拖放那四个虚函数各调得到（`_GetDragData`、`SetDragPreview`、`_CanDropData`、
`_DropData`），`at_position` 是控件内的点。取向在
`docs/adr/0001-engine-and-ui-one-declaration.md`「拖放走引擎的虚函数，刻度线和改大小手柄自己画」
那一节。

引擎**没有**的：刻度线、改大小手柄 —— 这两样自己算自己画。

**引擎那个整像素吸附不用拧** —— 实测结果是拧它对 `Control.Position` 没有影响。

**喂法两条**：喂系统那一层而不是引擎进程内那一层；分段交、段间让帧，
一次全交进去引擎来不及进「正在拖」那一档。

## 拖的时候浮出刻度线，贴上去就吸住

吸的是屏的中线、屏的四边、别的控件的边和它们的中间线。

**允许重叠**，重叠时后来摆的在上，编辑器里给「往前一层」「往后一层」两颗钮。

**加一张等距网格这一条否掉了** —— 网格把自由摆布变成分辨率，换一台屏就得重摆。

## 保存的时机

遮罩亮着的时候按保存，要等下一次休息才用新的。改完想看一眼得等下一次休息，
托盘左键点一下就切一次预览能顶一部分。
