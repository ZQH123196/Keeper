# 生活模式是一整套配置的快照，它住在一份名单和一份文档上

一整套配置的快照。这一份只写它的形状与机制。
产品行为在契约 `.scratch/keeper-contract/spec.md`「行为不变量」那一节。

## 装的是业务功能，不是这台机器的属性

界线住在声明表的**分域**上：

- 归「系统」那一域的键（界面语言、设置窗自己的配色、开机启动）**一律不进生活模式** ——
  **凡是归系统那一域的键一律不进生活模式**，**系统那域的键一律不进生活模式**。
- 其余各域（休息提醒、桌面日历、作息）连同那张休息流程表**全部进** ——
  **其余两域连同那张休息流程表全部进**。

判据是**域本身** —— 以后再加一个系统级设置，它自动在生活模式外面，
不靠人记得划。

## 一个生活模式 = 一份完整的配置文档

生活模式文件**就是一份配置文档**，格式和「导出」那一份完全一样。
于是「值超范围要夹」「读的时候宽容」「陌生的键不许有代价」
「导出→导入→导出逐字节相同」这一整套规矩**白送**，不为生活模式另立一份格式。

## 名单是一份索引

名字 → 那个文件叫什么。索引**当记录那一族对待** —— 读的时候借 JSONC 的容错
（认注释和尾逗号），写的时候程序整体重写，第一次写之前先留一份备份。

**文件名由索引分配递增号，且永不复用** —— 删掉一条之后下一个新生活模式拿更大的号。
撞名在这个程序里是要命的事，**结构上不撞**比「算出来大概不撞」可靠。

## 名字

任何合法 utf-8，上限 80 个字符（路径有长度），不许空、不许全是空格。
**重名当场拦住并指向覆盖**。

## 切一个生活模式 = 整份换掉

活的那一份里只保留「系统」那三条键，其余全部换成生活模式里的值，
走导入那同一条路，并留一份备份。**半个生活模式是不存在的**。

## 切换有两个动作

- **「切换」** 把窗里没保存的改动作废，并在状态栏说一声。
- **「保存并切换」** 先把窗里这份按保存落到磁盘再切，保存不成就说清为什么并且**不切**。

## 记录不跟着走

休息历史、休息清单、日历备注原样留在那儿。切换的是配置。

## 「我现在在哪个生活模式」不落盘

开窗拿活的那份配置和每个生活模式文件比一遍，一致就说「生活模式：写作」，
不一致就说「不在任何生活模式里」。界面状态不进配置。

## 读不通有三档，各说各的

| 那一档 | 说什么 |
| --- | --- |
| 名单读不通 | 生活模式这一族当成没有，并且**不覆盖磁盘上那份** |
| 某一个生活模式文件读不通 | 不切它，说清是哪个名字，别的照常能切 |
| 名字在名单里而文件不在 | 照实说，不静悄悄补一个默认 |

## 两个入口，同一个形状

- **托盘右键**出一颗子菜单：上半是生活模式列表、当前那个打勾，
  下半一条分隔线加「管理生活模式…」。
- **设置窗窗头**一颗按钮，点开一个菜单：上半切、下半管
  （存为新生活模式 / 覆盖当前生活模式 / 删掉这一条 / 打开管理器）。

两边同形状，省一次心智。托盘那一侧**只做「切」**：新建要输名字、覆盖要确认，
都不进那个模态循环。

设置窗里生活模式这一颗和「休息提醒 / 桌面日历 / 作息 / 系统」那几格标签**平级**，
因为它管的是全部配置，缩进某一个域里都不对。

## 菜单里不数项

契约、日志、注释里都不再写「七项」这种会抄过期的数字。菜单那一族要加一行时，
项数是从表上数出来的。

## 托盘子菜单在原生那一侧要补两样

一个「这一项是子菜单」的标志，和一条能接菜单句柄的「追加菜单项」形态
（现在那条的 id 是无符号整数，递不了句柄）。销毁用现成那条就够。

**键盘不用额外做事** —— 方向键、助记键、展开子菜单全归弹出菜单自己的模态循环。

## 磁盘上的目录名

这一族在磁盘上住在一个子目录里，老名字是 `modes`、现名字是 `lifemodes`，
第一次启动逐字节**改名**（和那四份配置文档同一趟，纪律一样：两份都在时哪一个都不动、
但要说出来）。

改名的缘由是**撞词**：`modes` 同时是配置里那张休息流程表的键名。
**配置那份文档的键一个字没动** —— 这一族换名字，不许顺手动到配置里去。
词汇表那一族的名字在 `GLOSSARY.md`。
