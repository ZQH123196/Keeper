# 预设生活模式是内置的只读模板，收进来才算自己的

随安装带来的那批只读模板。这一份只写它的形状与机制。
产品行为在契约 `.scratch/keeper-contract/spec.md`「行为不变量」那一节。

## 模板住在自己那个只读目录里

**永不写进用户的 `lifemodes`，程序升级也不碰用户收进来的副本。**
内置那份永远只读，「收一个」进来的是用户自己的副本。

## 格式就是那一份完整配置文档

注释里**逐块写出处**：哪一块、哪个数、来自哪条来源、哪里是演绎。
一份模板要能被当成一份配置文档读，这是它能被收进来的前提。

## 收一个进来走现成的导入那条路

复制成用户的生活模式、按现有规矩分配递增号；撞名走现有的「当场拦住并指向覆盖」。
导出 / 导入 / 逐字节回环那一整套规矩白送，不为预设另立一条路。

## 入口

画廊的入口在生活模式管理器和设置窗；**托盘不加入口** —— 托盘在这一族照旧只做「切」。

设置窗那一处是**生活模式那颗钮菜单里的一条**（2026-10-08：原先窗头还有一颗只管开画廊的
常驻钮，而菜单下半本来就有同一条，两处入口是同一个动作 —— 所有者定合并成一处，
留在菜单里那一处）。

## 为什么健康作息只剩卫健委一条

2026-10-02 所有者定夺。这条原来写的是「卫健委**与美国国家睡眠基金会 NSF**」两条来源。
**NSF 那一条到不了** —— `nationalsleep.org` 从这台机器出去是 SSL/502；能打开的
`sleepfoundation.org` **自己声明与 National Sleep Foundation 无隶属关系**，
而且同一个页面上「7–9 小时」（要点摘要）与它自己的年龄表「7 岁或以上」**自相矛盾**。

**一个数都没有从那里取。** 几条实测结果与抓取记录在
`docs/research/healthy-sleep-guidance.md`。要补第二条机构来源，是另一次定夺 ——
换一条到得了的机构指南重新考证。

## 读不通有几档，各说各的

| 那一档 | 说什么 |
| --- | --- |
| 目录整个不在 | 界面上说「预设那一族没有」，**不补一个默认** |
| 目录在、里面那一份读不通 | **那一行照样列出来**，带一句「读不通」 |
| 一个都没列出来 | 和「读不通」**不是一档** —— 那是「目录在而里面没有一份预设」 |

## 引不出来的数不进模板

一份模板里数得出来的来源，和它引的那几条，必须对得上。
嘉靖与周恩来那两份因此**整份都是演绎重构**，注释里逐块标了「演绎重构」。
